关屏用的是 `.forAppOnly`:**进程一退出,它关掉的屏就全部亮回**,主屏、菜单栏、Dock 可能随之搬家。
所以「换上新候选版」这件事本身就会改他的屏幕状态,不是无副作用的。

**Why:** 2026-10-22 我换候选版前跑了 `scripts/selfcheck.sh`,看到「菜单 2 项、都亮着」就以为没屏被关。
但自检是新起的进程,**看不到别的进程关掉的屏**(它的菜单只列活跃屏 + 自己关过的);同一输出里
「未点亮 ID=[1, 3, 5]」其实含内建屏,被我看漏。结果 kill 旧实例后内建屏亮回并成了主屏。
随后我用辅助功能接口按下面板里内建屏那一行,把它关回去,主屏回到原来那块外接屏。

**How to apply:**
1. 换实例前,先看**正在运行的那个实例**的面板(截图,或用辅助功能读各行的「已打开 / 已关闭」),
   记下哪些屏是关着的、哪块是主屏。别拿 selfcheck 的菜单项当依据。
2. 换完立刻按记录把那些屏关回去(辅助功能 `AXPress` 面板里对应行即可,本机终端已有辅助功能权限),
   再核对主屏与排列(`NSScreen.screens`)和换之前一致,然后才继续别的事。
3. 通用的「弄坏先恢复再汇报」见 [[restore-visibility-before-reporting]]。
