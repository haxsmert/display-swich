他要界面「照 Wi-Fi 菜单 / 系统原生」时,规格要**量出来**,不能目测或凭记忆;取证时有三个坑。

**Why:** 2026-10-23 他要图标、动效、锁都照 Wi-Fi 菜单。目测觉得差不多的地方,量出来全有偏差:
蓝色(强调色 ≠ Wi-Fi 用的系统蓝)、图形字号字重、锁的大小、行高、面板位置(Wi-Fi 那一套与 AppKit 的 NSMenu
几何不同)。上一轮我在真实背景上量悬停底,得出过「一致」;这次换白底、又拿录屏帧去比,一度得出相反结论——
录屏帧有颜色转换,同一块底截图是 234、录屏帧是 229。

**How to apply:**
- 背景要干净:临时起一个纯白、`ignoresMouseEvents` 的垫底小窗口(自己的进程,用完即杀,设自动退出),
  原生菜单与本面板都在它上面截图,同一像素管线逐项比。
- 规格用「候选对照」定:在**同样的系统玻璃**(且是前台的键窗口,后台玻璃是灰的)上把候选字号 / 字重 / 颜色
  一格格画出来,与原生比外接框 + 墨量(按背景差累加)+ 最深色,挑完全对上的那组。
- **颜色只认截图**;录屏只用来看时间(哪一帧出现、透明度曲线),帧内的相对值可比,绝对颜色不可比。
- 系统两行菜单项(`NSMenuItem.subtitle`)可以弹临时状态栏菜单实测,是「两行字的行」的原生依据。
- **测试里不要发合成的 Esc**:本 app 的面板不激活本 app,Esc 会落到当时的前台 app——他前台常是跑着
  Claude Code 的 Ghostty 窗口,Esc 会打断它。收面板用「再点图标」或点菜单栏空白处。
- 录屏时菜单栏会插进录屏指示图标,其他图标会挪位:点之前在录屏中截菜单栏,用模板匹配找准再点,对不上就不点
  (曾按旧坐标点到别的 app 的菜单)。录屏期间按键会被录屏程序吃掉。
- zsh 里 `log` 是内建命令,查系统日志要写 `/usr/bin/log`;app 里 `NSLog` 的插值文字在系统日志里是 `<private>`,
  要对时就临时写文件。
- 动到他的屏之前照 [[swapping-running-instance-relights-screens]] 定兜底;动效仍按 [[verify-animation-by-screen-recording]] 录屏验收。
