本仓库是公开的,`.claude/memory/` 也随仓库推上去。提交、发布说明、记忆里**不写**真实显示器名 / 品牌 / 型号、
用户名路径、拓展坞型号、序列号(界面截图用演示数据)。具体词表在本机 `.git/info/deidentify-patterns`
(`.git/info/` 不随推送走;词表本身就是要藏的词,所以不能进仓库,也不能写进这里)。

**Why:** 2026-10-23 我在代码注释里拿真实屏名举例,推上了公开仓库。提交前其实扫过,但扫描和提交用 `;` 串在一条命令里:
扫描把命中打印出来,提交照样往下走——扫描只是「看」,没有「拦」。补了一个提交删掉它,历史里仍留着
(早年历史里本来就有,2026-09 那次脱敏也只改文件、没改写历史)。

**How to apply:**
- **提交由本机 git 钩子把关**(2026-10-23 他同意后装在 MacBook 上,不进仓库):`.git/hooks/pre-commit` 查暂存区里
  **新增**的行(删掉的行不查,删漏网词的提交能过),`.git/hooks/commit-msg` 查提交信息;命中、或词表不在,都拒绝提交。
  装好后在临时仓库试过六种情况,真仓库里也试过一次被拒。
- 钩子管不到的要手动过同一个词表:发布说明、release 标题等走 `gh` 的文本,发之前 `grep -iEf .git/info/deidentify-patterns`。
- **换机器(如 Mac mini)时**:钩子和词表都不会随 clone 过来。先建词表(真实词从那台机器上的设备读,不从仓库抄),
  再从 MacBook 拷这两个钩子;没装之前,提交前手动 `git diff --cached | grep -iEf …` 过一遍,命中就停。
  新出现要藏的词(新显示器、新拓展坞)当场加进词表。
- 终端里看序列号只印末位;记忆、提交里写「同型号两台」「某型号」,不写名字。
- 改写公开历史要强推,必须他点头;默认只往前修。
